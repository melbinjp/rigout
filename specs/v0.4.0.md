# Rigout 0.4.0

Status: specified and built 2026-09-15.

## What rigout is

An MCP server that gives an AI agent a shell and the files on one machine. A person installs it
and starts it. The agent does the work.

Checked before this release: 553 PyPI downloads over 50 days, 3 stars, no forks, and no issues or
pull requests from anyone but the author. Nobody depends on the 0.3 tool set, so it is replaced
rather than kept alongside.

## Principles

1. **Built for the agent's turn budget.** Tools match what coding agents already use: run, read,
   write, edit, ls, glob, grep, and process for long jobs. Descriptions say when to use each one.
   Results are plain text, not narration.
2. **The person who installs it decides.** Starting rigout grants the agent the machine. There is
   no command blocklist and no bypass flag for the agent to toggle. The one protection is the
   bearer token on the URL, because a shared URL is reachable from the internet.
3. **Nothing is killed for time.** A command still running after about 50 seconds keeps running
   as a job, and the agent follows it with `process`. The 50 seconds exist only because common MCP
   clients abandon a call at about 60.
4. **One command for the person.** `rigout` serves locally, `rigout share` serves over a Cloudflare
   tunnel, `rigout url --client` prints the settings a client wants.
5. **Small enough to read.** Short README, behaviour tests, no documentation tests.

## Requirements

### Identity
1. The server identifies as `rigout`, with the package version.
2. On initialize it sends instructions: the workspace path, the shell `run` uses, and which tool to
   use for what.

### Workspace
1. `--workspace DIR` sets where relative paths and commands start. Default: the current folder.
2. Absolute paths work anywhere the user running rigout can reach.

### Tools (exactly these eight)
| Tool | Does |
|---|---|
| `run` | Runs a shell command. Returns exit code and output. Hands off to a job after `wait_seconds` (default 50). |
| `process` | `read` new output of a job (optionally waiting), `stop` it and its children, or `list` jobs. |
| `read` | Text file with line numbers; `offset` and `limit` (default 2000 lines). Refuses binary files. |
| `write` | Creates or replaces a whole file, creating parent folders. |
| `edit` | Replaces `old_string` with `new_string`. Fails with a next step if missing or not unique. Keeps CRLF. |
| `ls` | Directory listing: folders end with `/`, files show size. |
| `glob` | Files matching a pattern, newest first. |
| `grep` | Regex search, `file:line:text`, skipping `.git` and `node_modules`. Uses ripgrep when present. |

Every error says what to call next. Output is cleaned of terminal colour codes and stray carriage
returns, which broke live sessions in 0.2.

### Bounds that remain, and why
- Output per response: the last 100,000 characters per stream, with a note of how much was
  skipped. Larger responses stall clients.
- `read` returns 2,000 lines at a time and says how to get the rest.
- `glob`, `grep` and `ls` return the first 1,000, 500 and 1,000 entries, and say so.

### Transport and access
1. Streamable HTTP at `/mcp`, bearer token required. `/health` is open.
2. The token is created once, stored in the user's state folder, and kept across restarts.
   `rigout token --reset` replaces it.
3. `rigout stdio` serves a local client over stdio with no token.

### Commands
- `rigout` or `rigout serve [--workspace] [--host] [--port]`
- `rigout share [--workspace] [--port] [--tunnel NAME --hostname HOST]`: a quick tunnel by
  default (new URL each start), or a named Cloudflare tunnel for a fixed URL. Downloads
  cloudflared if it is missing.
- `rigout url [--client claude|cursor|vscode|raw]`
- `rigout token [--reset]`
- `rigout stdio [--workspace]`

On start it prints the workspace, URL, token and the Claude Code command, copies that command to
the clipboard when it can, and says plainly that anyone with the URL and token can run commands as
the user.

## Removed
The 0.3 tools (`execute_command`, `file_operations`, `bulk_file_transfer`, `docker_operations`,
`install_software`, `environment_setup`, `system_monitoring`, `get_hardware_info`,
`connect_hardware`, `manage_tunnels`, `get_server_activity`, and the four terminal-session tools),
the SSH endpoint mesh, the command security validator and `bypass_security`, the 30-second
default timeout, `connection.json` and setup tokens, the background lifecycle commands
(`start`, `stop`, `status`, `logs`), and the documentation-sentence tests.

## Tests
- Tools: each tool's success path and its error messages, CRLF edits, job hand-off and stop.
- HTTP: health, 401 without token, initialize name and instructions, tools/list, a tools/call.
- CLI: token persistence and reset, client settings, bare `rigout` means serve.
- Production validation: start the real command, connect with the MCP client, list tools, write,
  edit and run.
